Day one

Set up, then read, then ask

Before lunch

  • Laptop, accounts, and the repo cloned
  • The dev environment running one service

After lunch

  • Read the architecture note, not the whole wiki
  • Thirty minutes with your onboarding buddy

Nothing on day one is graded. The only goal is a running service and a name to ask.

Days two and three

The first change, end to end

1Pick a starter issue
2Write the test first
3Open a small pull request
4Watch it deploy
Small — under two hundred lines, one behaviour
Yours — you press the merge button, not your buddy

Days four and five

Review someone else's work

Read for intent

What is this change trying to do, and does the code say so?

Run it

Check out the branch and try the behaviour before commenting.

Ask, don't tell

A question teaches both people; a directive teaches one.

The hard rule: never approve a change you would not be comfortable deploying yourself.
